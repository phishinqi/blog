This is demonstration content for the V7 theme, not a report of a real project.

## Start with the document

A page can be useful before it becomes interactive. A heading, a clear paragraph, and a working link already form a remarkably durable interface.

Progressive enhancement means keeping that useful foundation intact. Search can make a collection easier to explore, but it should not be the only way to reach an article.

## Make the exceptional explicit

There are places where JavaScript earns its cost: a search dialog, a diagram, a small piece of feedback. The rest of the page can remain a document.

> The reader should never have to negotiate with the interface to read a sentence.

The test is not whether a feature is impressive but whether the page still works when it fails. A search dialog that never loads should leave every article reachable by navigation; a diagram that fails to render should leave its source readable. Both are cheap to design for and expensive to retrofit.

## Leave room for different readers

Someone may use a keyboard. Someone may prefer less motion. Another person may open a page on a narrow screen or a slow connection. Good defaults make these ordinary circumstances, rather than exceptions.
